# Native generation and durable receipts — 2026-09-30

The native client now executes generation and saves a receipt before reporting
success. This extends the earlier context-assembly and inference checkpoints.

With `--store PATH --namespace NAME`:

```text
context generate PRINCIPAL MODEL BYTE_BUDGET MAX_TOKENS PROMPT [URI...]
context receipt PRINCIPAL RECEIPT_ID
```

Generation is synchronous, greedy (`temperature=0`, `top_p=1`, `top_k=0`), with
seed 42 and a 1 MiB output-byte cap. It loads the specified native model directly,
uses the authorized context bridge and returns JSON containing receipt ID, text,
prompt tokens and generated tokens. It does not spawn another executable.
There is no streaming or cancellation in this command yet. Principal arguments
are a trusted local interface, not remote authentication.

The client dispatcher moved into the `fyodor-client` C library, which links
`fyodor-inference`. `fyodor-app` remains independent of the engine, and the
inference bridge reuses `nya-engine`. Other native interfaces can call the same
command dispatcher or typed service APIs. The C17 CPU executable is 1,926,993
bytes in this build; the earlier resource-only size is historical.

## Stored record and access

Database schema 3 adds immutable `context_receipts`. Validated migrations from
schemas 1 and 2 run in the opening transaction. Existing resources, history and
grants survive; receipt records start empty. The stored record contains:

- Originating principal, namespace, OS-random UUID and creation timestamp.
- Exact engine input prompt and returned output text.
- Source URIs, original revisions, included byte ranges and original lengths.
- Native prompt/output token counts and stop reason.
- Sampling temperature, top-p, top-k, seed, output-token request and model context
  capacity, plus the model path and file size.

Seeds and model sizes are decimal JSON strings to preserve full U64 values.
Model path and size do not prove immutable model identity; a content hash and
persistent model-registry identity remain future work. This is not a cryptographic
attestation or guarantee of reproducibility on a different model/provider.

A single SQLite insertion commits the complete receipt. If saving fails after
inference, the bridge returns failure and no successful receipt/result; inference
itself cannot be rolled back. Callers should distinguish that diagnostic from
an inference failure when deciding whether to retry.

Receipt inspection requires the original principal and namespace, plus current
READ permission on every source. Deleted/revoked sources hide receipts too,
including sources omitted by the context budget. Checking authorization and
reading the receipt occur in a single SQL statement snapshot. Regranting access
can make the historical receipt visible again. Source edits do not rewrite the
stored prompt or attribution. These checks do not retract text already delivered
to a caller, and local filesystem access remains outside the permission boundary.

The resource-package importer cannot import or mutate execution receipts.
The completion recorder is a trusted internal API; it is not exposed as a remote
or package-based claim that arbitrary text was generated by a model.

Writing previews now additionally record structured `writing_mode` metadata
(`generate`, `rewrite`, or `continue`); ordinary generation records null.
Older receipts without this field remain readable but cannot authorize a
Writing receipt-linked save. Accepted edits reference the immutable receipt
from resource provenance; see [Writing generation](WRITING_GENERATION.md).

  generation despite the configuration including CUDA.
- Native CLI process test executes resource creation, grant, actual model
  generation, receipt inspection in a fresh process, revoke, denied receipt read,
  and denied new generation. It uses a trained tiny transformer, not a mocked
  completion, and retains the existing Unicode-path and JSON checks.
- C integration verifies exact prompt/output persistence, original prompt after
  source modification, reopen, namespace/owner denial, revocation, exact source
  revision, and an injected receipt-insertion failure. The failed insertion leaves
  the receipt count unchanged and returns no successful result.
- Schema-2 migration preserves grants; schema-1 migration preserves resource
  content/history while creating no grants. Both are exercised in native tests.

This establishes a real local context → model request → persisted provenance
path. It does not complete layered/indexed context, principal-scoped mutations,
remote execution, Desktop/TUI integration, the model registry, or the remaining
workspaces in the product brief. No performance, real-large-model, GPU generation
or platform other than Windows claim is made here.
