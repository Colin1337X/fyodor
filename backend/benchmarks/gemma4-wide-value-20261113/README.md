# Wide attention value reduction, 2026-11-13

Original Fyodor experiment based on the existing `CUDA/resident.cu` partition algorithm. No third-party source was copied. The adjacent-column loop reuses scores across sixteen output columns while retaining each output's token and warp accumulation order. C host dispatch remains in `CUDA/resident.inc`; optional CUDA C++ is isolated under `optcpp/attention`. Four-column source is retained for reproduction; the eight-column candidate is generated by `common.py`. Only `wide_value16.cu` is included by the runtime build.

Build with `-DNYA_ENABLE_WIDE_VALUE=ON` and set `NYA_CUDA_WIDE_VALUE=1`. Both default off. Existing long graph topology, single-token decode, and widths 256/512 are required. Reference execution, prefill, short graph, and other shapes retain existing dispatch. Missing source or disabled optcpp omits the feature. Runtime symbol lookup failure retains native dispatch. There is no Vulkan/ROCm/MLX implementation of this experiment yet.

## Correctness

`check_kernel.py` compares 4/8/16-column candidates against native attention byte-for-byte for widths 64, 130, 256, and 512; one/four partitions; host/device position; multiple queries; sliding/full attention; ring wrapping; finite outputs and guards. Production sixteen-column code also exercises a deliberately unaligned V pointer. `oracle.json` includes source hash and NVRTC options. All four compute-sanitizer tools completed with exit zero; commands and logs are retained in `sanitizers.json` and corresponding logs.

`model_oracle.c` toggles only the runtime option. C17 Gemma 4 12B Q4_K_M with ring KV passed 257, 2049, and 8194 tokens, including the short/long graph boundary, graph replay, all logits (exact), retained KV snapshots (exact), and reset (exact). C23 linear KV passed 2049 tokens. Build/binary hashes and environment are in the results JSON. Compile the harness against `libnya-engine.a`; `run_model.py [build-directory] [ring:0|1] [token-counts...]` reproduces the runs. The model is the user-provided file under `E:/models`; full runs use F32 KV, packed projections, and short-context FDPP. Model SHA256: `59656d7494d6376ca97e9e20b64ea2e16cd97f12ec6d47bfccba91cb785b5134`.

## Isolated timing, not accepted throughput

`probe.py` runs four-partition attention plus combine in graphs, twenty operations per graph, three warmups, five samples of ten replays, forward/reverse variant order. Repeated buffers are cache-friendly and desktop GPU activity remains. RTX 5060 Ti SM120. All results explicitly mark acceptance false.

Final guarded candidate: width 512/full attention/8192 position measured 0.967116 ms native versus 0.378056 ms sixteen-column (2.56x). Width 256/window 1024/ring measured 0.0403012 versus 0.0288130 ms (1.40x). Raw samples, standard deviations, environment snapshots and source hash are in `probe-results.json`. Earlier four-column-only evidence is retained separately. These are synthetic kernel measurements, not full-model throughput, hardware-counter evidence, or llama.cpp scores. Accepted Gemma scores remain 85.61% short and 106.87% at 8K. The 125% target is not reached.

Physical-removal verification passed: the native C build/test lifecycle completed 80 tests with four expected ROCm/MLX skips (`physical-removal.log`). A separate CUDA-enabled engine build from the same copy, with optcpp absent and wide-value explicitly requested, succeeded and omitted `NYA_WIDE_VALUE` (`physical-removal-cuda.json`, `.log`). This verifies graceful build exclusion; CPU smoke timings are not performance acceptance.
